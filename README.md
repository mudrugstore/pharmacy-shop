# เว็บร้านขายยาออนไลน์ (Flask + Supabase + Render)

เว็บร้านขายยาออนไลน์ รองรับผู้ใช้ประมาณ 200 คน แยกส่วนลูกค้าและผู้ดูแลระบบ
เก็บข้อมูลใน Supabase (PostgreSQL) เก็บรูปใน Supabase Storage และ deploy ฟรีบน Render

## ฟีเจอร์

**ฝั่งลูกค้า**
- สมัครสมาชิกด้วยชื่อ + เบอร์โทร + รหัสผ่าน (ไม่มี OTP)
- เข้าสู่ระบบด้วยเบอร์โทร + รหัสผ่าน
- ดูสินค้าแยกตามหมวดหมู่
- ตะกร้าสินค้า + สั่งซื้อ (ไม่มีระบบจ่ายเงิน แสดงข้อความให้ติดต่อร้าน)
- สินค้าพรีออเดอร์ (สั่งจอง แล้วร้านติดต่อกลับตามเบอร์)
- ดูประวัติการสั่งซื้อและพรีออเดอร์ของตัวเอง

**ฝั่งผู้ดูแลระบบ (admin)**
- จัดการหมวดหมู่ (เพิ่ม/ลบ)
- จัดการสินค้า (เพิ่ม/แก้ไข/ลบ) + ตั้งสต็อก + อัปโหลดรูป (บีบอัดอัตโนมัติ)
- ดูคำสั่งซื้อแบบละเอียด + อัปเดตสถานะ
- ดูรายการพรีออเดอร์ พร้อมเบอร์ลูกค้าเพื่อติดต่อกลับ
- จัดการผู้ใช้: รีเซ็ตรหัสผ่าน (ปลดล็อกให้ตั้งใหม่เอง) และลบผู้ใช้
- ตั้งค่าร้านผ่านเว็บ: ชื่อร้าน เบอร์โทร ที่อยู่ เวลาทำการ และข้อความแจ้งลูกค้า (แก้ได้เองไม่ต้องแก้ env)

## เทคโนโลยี
- Python 3.12 / Flask
- psycopg v3 (เชื่อม PostgreSQL)
- Supabase (ฐานข้อมูล + Storage)
- gunicorn + Render (deploy)

## คู่มือตั้งค่า Supabase (ทีละสเต็ป)

### 1. สมัครและสร้างโปรเจกต์
1. ไปที่ https://supabase.com แล้วสมัคร (ใช้ GitHub/อีเมล)
2. กด **New Project** ตั้งชื่อ ตั้งรหัสผ่านฐานข้อมูล (**จดไว้ให้ดี**) เลือก Region ใกล้ไทย เช่น Singapore
3. รอสร้างโปรเจกต์สักครู่

### 2. เอา Connection String (DATABASE_URL)
1. ไปที่ **Project Settings > Database**
2. หาหัวข้อ **Connection string** เลือกแบบ **URI** และเลือกโหมด **Session pooler** (หรือ Transaction pooler)
3. คัดลอก URI มา แล้วแทน `[YOUR-PASSWORD]` ด้วยรหัสผ่านฐานข้อมูลที่ตั้งไว้
4. ค่านี้คือ `DATABASE_URL`

### 3. ตั้งค่า Storage สำหรับเก็บรูปสินค้า
1. ไปที่เมนู **Storage > Create a new bucket**
2. ตั้งชื่อ bucket เป็น `product-images`
3. เปิดสวิตช์ **Public bucket** (เพื่อให้รูปแสดงบนเว็บได้)
4. กด Create

### 4. เอา API keys
1. ไปที่ **Project Settings > API**
2. คัดลอก **Project URL** -> `SUPABASE_URL`
3. คัดลอก **service_role key** (อยู่ใต้ Project API keys) -> `SUPABASE_SERVICE_KEY`
   - คีย์นี้เป็นความลับสูง ใช้เฉพาะฝั่ง server ห้ามเปิดเผย

## คู่มือ deploy บน Render (ทีละสเต็ป)

### 1. อัปโค้ดขึ้น GitHub
สร้าง repo บน GitHub แล้ว push โค้ดนี้ขึ้นไป (ไฟล์ `.env` จะไม่ถูกอัปเพราะอยู่ใน `.gitignore` อยู่แล้ว)

### 2. สร้าง Web Service บน Render
1. ไปที่ https://render.com แล้วสมัคร/เข้าสู่ระบบ
2. กด **New > Web Service** แล้วเชื่อม GitHub repo ของคุณ
3. Render จะอ่านไฟล์ `render.yaml` ให้อัตโนมัติ (Build: `pip install -r requirements.txt`, Start: `gunicorn wsgi:app`)
4. เลือกแพลน **Free**

### 3. ตั้งค่า Environment Variables บน Render
ไปที่แท็บ **Environment** ของ service แล้วใส่ค่าต่อไปนี้:

| Key | ค่า |
|-----|-----|
| `DATABASE_URL` | connection string จาก Supabase (ขั้นที่ 2) |
| `SUPABASE_URL` | Project URL จาก Supabase |
| `SUPABASE_SERVICE_KEY` | service_role key จาก Supabase |
| `SUPABASE_BUCKET` | `product-images` |
| `ADMIN_PHONE` | เบอร์โทรของแอดมิน เช่น `0812345678` |
| `ADMIN_PASSWORD` | รหัสผ่านแอดมินเริ่มต้น |
| `ADMIN_NAME` | ชื่อแอดมิน |
| `STORE_NAME` | ชื่อร้าน (ค่าเริ่มต้น แก้ผ่านหน้า "ตั้งค่าร้าน" ได้ภายหลัง) |
| `STORE_PHONE` | เบอร์โทรร้าน (ค่าเริ่มต้น แก้ผ่านหน้า "ตั้งค่าร้าน" ได้ภายหลัง) |

> `SECRET_KEY` ไม่ต้องใส่ Render จะสุ่มให้อัตโนมัติ (ตั้งไว้ใน render.yaml แล้ว)
>
> `STORE_NAME` / `STORE_PHONE` ใช้เป็นแค่ค่าเริ่มต้นตอนรันครั้งแรก หลังจากนั้น
> แอดมินแก้ชื่อร้าน เบอร์โทร ที่อยู่ เวลาทำการ และข้อความต่างๆ ได้เองที่หน้า
> **แผงแอดมิน > ตั้งค่าร้าน** โดยไม่ต้องแก้ environment variable อีก

### 4. Deploy
กด **Create Web Service** รอ build เสร็จ จะได้ URL เช่น `https://pharmacy-shop.onrender.com`
เข้าใช้งานได้ทันที บัญชี admin จะถูกสร้างอัตโนมัติจากค่าที่ตั้งไว้

## ข้อควรรู้เรื่องแพลนฟรี

- **Render free web service**: จะ "หลับ" หลังไม่มีคนเข้า 15 นาที คนเข้าครั้งแรกหลังหลับจะช้า 30-60 วิ แล้วใช้ได้ปกติ
- **Supabase free**: โปรเจกต์จะ "พัก" ถ้าไม่มีการใช้งานฐานข้อมูลเกิน 7 วัน (ข้อมูลไม่หาย) แต่ถ้ามีคนใช้ประจำจะไม่พัก
- ถ้าอยากกันไม่ให้หลับ/พัก สามารถตั้งบริการ ping เว็บเป็นระยะ (เช่น UptimeRobot ฟรี) ชี้มาที่ URL ของเว็บ

## ทดสอบการเชื่อมต่อฐานข้อมูล (ทางเลือก)

หลังตั้งค่า `.env` ครบแล้ว รัน `python _dbtest.py` เพื่อทดสอบ flow ทั้งหมด
(สคริปต์จะ **ลบและสร้างตารางใหม่** จึงควรรันกับฐานข้อมูลทดสอบเท่านั้น ไม่ใช่ฐานข้อมูลที่มีข้อมูลจริง)
